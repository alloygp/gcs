8
Hook up Resend
Verify the sender domain so the site can deliver emails
Email ▶

Step 1 — Add the domain in Resend

Go to resend.com → Domains → Add Domain and enter the client domain. Resend will give you DNS records to add — they'll look like this:
TypeNameValue
TXT resend._domainkey p=MIGf... (DKIM key Resend generates)
MX send feedback-smtp.us-east-1.amazonses.com (priority 10)
TXT send v=spf1 include:amazonses.com ~all

Add these wherever the client's DNS is managed (GoDaddy, Cloudflare, etc.). Verification usually takes a few minutes.

Step 2 — Get your Resend API key

Resend → API Keys → Create API Key → name it "[Client] Production" → copy it. You'll add this to Vercel in Step 9.

Wire up forms & test

Forms ▶

Add environment variables in Vercel

These values live in the .env file the kickoff script generated — open that file and copy them into Vercel under Project → Settings → Environment Variables. Each variable has an environment scope — set it exactly as shown so dev/staging don't accidentally fire production analytics or send real emails.
VariableValueEnvironment
RESEND_API_KEY The API key you created in Resend (Step 8) Production & Preview
INTERNAL_NOTIFY_EMAIL The inbox that receives form submissions (e.g. hello@clientdomain.com) Production & Preview
PUBLIC_ENV production Production only
PUBLIC_ENV development Preview only
GA_MEASUREMENT_ID G-XXXXXXXXXX — from Google Analytics Production & Preview
MAILCHIMP_API_KEY From Mailchimp → Account → Extras → API keys Production & Preview
MAILCHIMP_LIST_ID Audience ID from Mailchimp → Audience → Settings Production & Preview

Test the contact form

Forms are the most common thing to silently break after a deploy. Astro's server-side form handling needs specific syntax to work in a deployed environment — if a form works locally but fails on Vercel, it almost always means the form action or API route isn't wired up correctly for SSR. Claude can fix this in seconds.

If the form isn't working — ask Claude to fix it

Open the client's Cowork project and paste this prompt. Claude will audit the form code and fix the deployment syntax automatically.

Add honeypot spam protection

A honeypot is a hidden field bots fill in but real users never see. Any submission that includes it gets silently dropped — no CAPTCHA needed, no friction for real visitors. This should be on every form.

Mobile optimization
Check every page on mobile, fix layout issues with Claude
Mobile ▶

Review each page on mobile

Open the staging site on your phone, or use Chrome DevTools — right-click anywhere → Inspect → click the phone/tablet icon in the top-left of the panel. Go through every page and look for anything that's broken, cramped, or hard to read.

Fix any issues with Claude

Describe exactly what you're seeing and on which page. The more specific you are, the faster Claude will fix it.

Internal review & client approval

Review ▶

Add the site to Pastel

Pastel is a website annotation tool — it lets reviewers click anywhere on a live page and leave a comment pinned to that exact element. No screenshots, no vague emails. Go to usepastel.com, create a new review, and paste in the staging URL.

Get Claude to build a page-by-page review list

Pastel lets you navigate to any page within the review by appending the path to the review URL. Ask Claude to generate a full list of every page on the site with clickable Pastel links so the review team can jump directly to each page without navigating manually.

Internal review

Send the Pastel review link to the internal team before it goes to the client. Use the page-by-page checklist to make sure every page gets eyes on it.

Client review

Once the internal team is satisfied, send the same Pastel link to the client. They can click on any element and leave a comment directly on the page — no back-and-forth over email trying to describe what they mean.
